# 开头阅读体验 Gate

公众号文章发布前必须检查首屏阅读体验。它不是标题 gate，也不是风格 gate，而是判断读者点开后是否愿意继续读。

## 触发时机

以下阶段必须执行：

- 方案卡生成前：每个方向要说明开头策略和索引策略。
- 候选稿生成前：确认读者进入文章的路径。
- 发布版锁定前：检查最终开头是否清楚。
- HTML / 发布包 ready 前：检查顶部卡片、内容索引和第一屏排版。
- 用户反馈“开头弱 / 不知道文章讲什么 / 需要索引 / 继续读动力不够”后：重新执行本 gate。

## 首屏必须回答

前 300 个中文字符内，至少要回答：

- 这篇文章讲什么。
- 为什么现在值得读。
- 读完能得到什么。

如果文章由截图、事件或实验启动，开头还要交代：

- 发生了什么现场。
- 这个现场为什么不只是热闹，而值得抽象成判断。

## 内容索引类型

“内容索引”默认指目录型索引，不是观点预告。

### 目录型索引（默认）

用于让读者快速知道全篇结构。必须写清：

- 全篇分几部分。
- 每一部分讲什么。
- 每一部分解决什么读者问题。

适合：长文、流程复盘、方法论、判断型文章、截图很多的文章。

示例结构：

```text
这篇文章主要分 4 部分：
- 第一部分：现场复盘。说明我看到了什么。
- 第二部分：关键判断。解释这件事为什么重要。
- 第三部分：边界问题。说明哪些事情不能交给 AI。
- 第四部分：使用建议。给个人和企业可执行的下一步。
```

### 观点型索引

用于先抛核心判断。它可以增强传播，但不能冒充目录。

适合：短评论、观点冲突很强、正文结构很简单的文章。

如果用户说“内容索引”，不要默认使用观点型索引。只有用户明确说“先给观点 / 先给几个判断 / 先抛结论”时才用。

### 场景型导读

用于先交代读者场景和收益。

适合：教程、工具使用、流程实操文章。

## 顶部组件顺序

默认顺序：

```text
顶部金句 / 导语卡
→ 内容索引或导读
→ 现场 / 问题 / 第一段正文
```

顶部金句卡负责情绪和判断，不负责目录。内容索引负责结构，不要只重复金句。

## 不合格模式

以下情况必须重写开头：

- 内容索引只写“现场 / 判断 / 边界”这类抽象词，读者不知道每部分具体讲什么。
- 顶部金句、内容索引和标题互相重复。
- 第一屏只展示截图，没有说明截图为什么重要。
- 开头只有作者自嗨，读者不知道自己能得到什么。
- 目录型索引列了 3-4 个词，但没有说明每部分解决什么问题。

## 输出记录

方案卡、候选稿或发布收尾中至少记录：

- 开头模式：现场切入 / 问题切入 / 反常识切入 / 目录型索引 / 观点型索引 / 场景型导读。
- 是否使用内容索引：是 / 否。
- 索引类型：目录型 / 观点型 / 场景型。
- 前 300 字检查：讲什么 / 为什么现在读 / 读完得到什么。
- 是否与标题、顶部金句重复。
