# 公众号修订学习闭环

用于把“AI 原稿 → 用户终稿”的差异沉淀成作者写作规律。目标不是让 AI 模仿单篇修改，而是持续学习用户真实改法。

## 1. 必须保留的双稿

候选稿进入用户修改前，必须在成稿区保留 AI 原稿；用户满意并进入发布前，必须再保留用户终稿。

推荐结构：

```text
content-factory/final-drafts/YYYY-MM-DD_主题/
├── ai-draft-v1.md            # AI 原稿，不覆盖
├── final-user-edited.md      # 用户满意终稿 / 待发布稿
├── revision-diff.md          # 本篇逐段差异
└── revision-learning.md      # 本篇可复用观察
```

兼容旧命名：如果已有 `narrative_v1.md`、发布版 Markdown 或工作台稿，不强制迁移；但必须在工作台 / 候选稿记录里写明：

- AI 原稿路径
- 用户终稿路径
- 是否已生成 `revision-diff.md`
- 是否已写入 `修改规律.md`

禁止覆盖 AI 原稿来“保存最新稿”。

## 2. 用户终稿的判定

以下任一情况可视为用户终稿：

- 用户在对话中直接给出关键改写方向或替换句，并要求继续发布

- 用户明确说“满意 / 可以发布 / 用这个 / 定稿”
- 已从该稿生成发布版、HTML 或发布包
- 用户在待发布稿里完成修改并要求继续发布

如果无法判断哪个文件是用户终稿，先停下来确认，不做学习沉淀。

## 3. 单篇差异分析

对比 AI 原稿和用户终稿，至少分析：

- 是否出现“自我坦白 / 自我警告”式补写：例如作者把对某类人的批评落回自己身上，避免居高临下。

- 删除了什么：空泛铺垫、AI 套话、重复解释、弱判断、虚假顺滑过渡
- 改了什么：标题、开头、段落顺序、判断句、概念解释、语气强弱、句长节奏
- 加了什么：个人经历、企业现场感、具体例子、截图证据、行业判断、金句
- 保留了什么：用户认可的判断、结构、表达、故事锚点、配图逻辑
- 发布链路影响：标题、摘要、配图、HTML、发布包是否需要同步

单篇结论写入同目录 `revision-learning.md`。单篇观察只作为“待验证规律”，不能直接改写稳定风格基线。

## 4. 跨篇进化学习

当累计至少 3 篇有 AI 原稿和用户终稿的样本后，执行跨篇学习：

- 汇总多篇 `revision-learning.md`
- 提取跨篇重复出现的删改加规律
- 区分稳定规律和待验证规律
- 写入 `content-factory/writing-assets/修改规律.md`

`修改规律.md` 只写可执行规则，不写泛泛评价。格式建议：

```text
## 跨篇稳定规律
- 规则：
  - 触发场景：
  - 写作动作：
  - 反例：
  - 样本来源：

## 待验证规律
- 观察：
  - 还需样本：
```

## 5. 下次写作调用规则

候选稿前，和其他写作资产一起读取 `修改规律.md`。使用时遵守：

- 稳定规律优先于模型默认写法
- 待验证规律只能作为提醒，不能机械套用
- 与用户当前原文冲突时，保留当前原文优先
- 与事实核验冲突时，事实优先
- 与表达禁改规则冲突时，表达禁改规则优先

## 6. 推荐脚本

可用脚本生成单篇差异和学习草稿：

```bash
python3 -X utf8 "scripts/build_revision_learning.py" \
  --root "your-vault" \
  --package-id "YYYY-MM-DD_主题" \
  --ai-draft "content-factory/final-drafts/YYYY-MM-DD_主题/ai-draft-v1.md" \
  --final-draft "content-factory/final-drafts/YYYY-MM-DD_主题/final-user-edited.md"
```

脚本只生成候选观察；是否把某条规律提升为稳定规律，需要 agent 基于多篇样本判断。
