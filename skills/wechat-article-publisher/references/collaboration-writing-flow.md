# 协作扩写流程

用于处理素材、核心段、观点种子、截图线索和半成稿，目标是把“作者已经开始表达的东西”推进为可发布文章，而不是替代作者重写。

## 输入模式判断

优先判断输入属于哪一类：

- 核心段模式：已有 150 字以上、风格和判断明显的原文
- 观点种子模式：只有标题、观点句、几个关键词
- 事件扩写模式：新闻、截图、链接、事件线索
- 素材成文模式：多段摘录、零散材料、尚无明确论点

如果无法判断，先停下来确认输入模式，不直接写全文。

## 固定推进顺序

```text
Phase -1 历史已发布链接刷新
→ Phase 0 输入诊断
→ Phase 0.5 素材池建立 / 更新
→ Phase 1 MECE 分析 + 金字塔逻辑图
→ Phase 1.5 写作阶段真实性 / 资料核验
→ Phase 1.8 创造运行时发散
→ Phase 2 2-3 个方案卡（含插图决策）
→ Phase 2.5 风格对齐
→ Phase 3 双源初稿 + 候选稿
→ Phase 3.2 双源稿 / 用户终稿保存
→ Phase 3.5 相关产物同步检查
→ 成稿 / 发布版
→ Phase 3.8 发布前真实性复核
→ Phase 4 修订学习
```


## Phase -1 历史已发布链接刷新

每次启动新公众号文章工作流，先刷新历史链接池，再做选题、方案卡、标题和正文链接选择。

执行顺序：

```bash
python3 -X utf8 "scripts/sync_wechat_published_backend.py" \
  --root "your-vault" \
  --json-output "content-factory/writing-assets/published-articles-snapshot.json"

python3 -X utf8 "scripts/backfill_published_links_from_backend.py" --root "your-vault"
```

要求：

- 成功时，后续使用最新 `published-links-index.md` 作为历史文章链接池
- 后台不可用时，记录失败原因，不声称已刷新，并使用现有索引继续
- 这个步骤解决的是“历史文章链接池新鲜度”，不是当前文章正式发布后的单篇回填

## Phase 0.5 素材池建立 / 更新

每篇文章必须有对应素材池目录：

```text
content-factory/material-pool/YYYY-MM-DD_主题/
├── source.md
├── research-brief.md      # 触发真实性核验时必须生成 / 更新
└── assets/                # 截图、源图、用户提供图片
```

`source.md` 至少记录：

- 原始收件箱 / 来源笔记链接
- 原始输入或核心段
- 核心判断
- 写作方向
- 已使用的写作资产
- 截图和源视觉材料清单
- 这些素材在后续文章中的处理结果

如果素材来自 `00_收件箱`，不能只在工作台引用收件箱原文；必须把可追溯摘要写入素材池。

## Phase 1 必做项

必须明确：

- 当前输入模式
- 素材池路径和更新状态
- 写作依据优先级
- 文章真正要回答的问题
- 原素材已经说清楚了什么
- 缺失的逻辑链、过渡、论据、案例位、数据位、引用位
- AI 最容易改坏原味的地方
- 不可改边界
- 本篇必须调用哪些写作资产
- 风格对齐结果
- 是否需要个人故事锚点
- 文章为什么应该由作者来说
- 需要不要封面 / 正文插图，正文图预计几张
- 用户点名要求补上的概念有哪些
- 创造运行时的稳定核心：核心判断、作者位置、读者问题、情绪锚点、事实边界

## Phase 1.5 写作阶段真实性 / 资料核验

真实性不是发布时才检查。进入方案卡、候选稿或扩写前，只要触发事实核验条件，就读取 `truth-and-fact-checking.md` 并创建 / 更新 `research-brief.md`。

遇到以下情况默认启用：

- 当前事件
- 公司 / 产品 / 政策 / 价格 / 市场数据
- 技术机制或产品能力判断
- 命名人物、报告、案例
- 截图中提到的外部事实
- 标题、摘要、内容索引或主判断依赖事实
- 用户明确要求带资料校验

资料优先级：

1. vault 内部资料与用户原文
2. 飞书 / Lark 内部资料
3. 官方 / 一手来源
4. 高质量二手来源
5. 开放网络与社交讨论，仅作线索

必须把资料校验结论写入 `research-brief.md`，至少区分：

- 用户自己的判断 / 个人体验 / 实测过程
- 已核验事实
- 一手来源和可用支撑材料
- 二手来源和线索材料
- 冲突与未解项
- 不能写成确定事实的占位符
- 已降级写法

候选稿生成前，不能把未核验外部事实写成确定事实；只能写成个人观察、截图显示、待核验占位或删去。

## Phase 1.8 创造运行时发散

进入方案卡前读取 `creative-runtime.md`。先定义稳定核心，再做多方向发散。

默认至少生成 3 个结构上不同的方向：

- 熟悉但更清楚：降低理解成本
- 明显差异化：增强传播记忆点
- 大胆但可理解：突破同质化，但不偏离事实和作者身份

每个方向都要标注：偏离点、新颖度、方法论、情绪锚点、反同质化处理和风险。

## Phase 2 方案卡

粗输入场景必须先出 2-3 个方向，再等用户选。

默认方案：

- 方案 A：保守增强
- 方案 B：叙事增强
- 方案 C：评论强化

每张方案卡至少包含：

- 标题角度
- 核心论点
- 开头策略
- 结构大纲
- 保留什么
- 新增什么
- 不改什么
- 风险与代价
- 推荐理由
- 个人锚点策略：用哪个真实经历 / 放在哪一段 / 如何服务主判断
- 配图策略：封面方向、正文图是否需要、预计张数、素材来源或生成方式

方案卡可以先多选候选，但最终稿必须收敛到一条主线；正文图可以多选落位。

## Phase 2.5 风格对齐

进入候选稿前，读取 `style-alignment-gate.md`，完成风格对齐检查。至少记录：读取了哪些风格资产、命中了哪些规则、保留哪些原味、哪些表达需要避免。

如果用户上一轮反馈“像 AI / 不像我 / 没人味”，先回退到原稿或 AI 原稿，只做轻量结构微调，不继续扩写新内容。

## Phase 3 双源初稿 + 候选稿

只有在用户已选方向，或明确说“全自动按推荐走”时才进入。

协作扩写默认先形成两份 AI 初稿，再融合成候选稿：

- Codex 直写稿：由当前 agent 直接写，保存为 `ai-draft-v1.md` 或 `codex-draft-v1.md`。
- Claude Code / Multica 稿：由外部写作 agent 写，保存为 `claude-draft-v1.md` 或 handoff 指定路径。

融合前必须比较两份稿：结构、开头、作者口吻、个人锚点、截图处理、事实边界、可发布性。最终候选稿可以以其中一份为主，但必须记录融合依据和舍弃理由。

如果当前环境无法调用 Claude Code / Multica，必须记录原因；不能把单份 AI 初稿假装成双源初稿。

候选稿要求：

- 不混入 MECE、金字塔、方案卡分析
- 核心段模式下保留原文主干
- 非核心段模式下明确哪些内容来自事件、历史风格、占位补充
- 升级到发布版前，先做 coverage check
- 候选稿给用户修改前，保存 AI 原稿路径，禁止覆盖
- 不把工作台标记（📍/✏️/⚠️ 等）带入正文
- 判断型文章不能是纯第三方评论；必须有作者个人痕迹，或记录不用的理由


## Phase 3.2 双源稿 / 用户终稿保存

候选稿进入用户修改前，必须保留两份 AI 初稿；用户确认满意或进入发布版前，必须保留用户终稿。

推荐路径：

```text
content-factory/final-drafts/YYYY-MM-DD_主题/ai-draft-v1.md       # Codex / 当前 agent 直写稿
content-factory/final-drafts/YYYY-MM-DD_主题/claude-draft-v1.md   # Claude Code / Multica 稿
content-factory/final-drafts/YYYY-MM-DD_主题/final-user-edited.md # 融合后用户终稿
```

兼容旧稿件时，也要在候选稿或工作台里记录实际路径。禁止用用户终稿覆盖任一 AI 初稿。

## Phase 3.5 相关产物同步检查

候选稿、改稿、成稿、发布版、HTML 或发布包发生变化后，读取 `article-generation-consistency-checklist.md`，检查已存在的相关产物是否需要同步。

必须输出：

- 已同步：实际改过哪些产物
- 已检查无需同步：哪些产物存在但无需改，原因是什么
- 待人工确认：事实、IP、版权、后台正式发布等
- 阻塞项：缺少素材、权限、最终链接等

不要只说“文章已改好”。

## Phase 3.8 发布前真实性复核

发布版锁定、发布包 ready 或远端草稿创建前，读取 `truth-and-fact-checking.md`，对标题、摘要、顶部卡片、内容索引、正文、图注、截图描述和链接做真实性复核。

必须确认：

- 每个确定性事实能回到 `research-brief.md` 或用户原始材料
- 未核验项已降级为个人体验、观察、判断或截图显示
- 截图描述与实际截图逐张一致
- 中心事实无法核验时停止进入发布包 / 草稿箱

## Phase 4 修订学习

当 AI 原稿和用户终稿都存在时，生成本篇 `revision-diff.md` 和 `revision-learning.md`。累计至少 3 篇样本后，提炼跨篇稳定规律，更新 `writing-assets/修改规律.md`。详见 `revision-learning-loop.md`。

## 必停场景

以下情况必须停：

- 输入模式不明
- 核心论点不明
- 用户说“改得不像我”“太 AI”
- 用户还没选方案
- 关键事实无法核验且会影响主论点
