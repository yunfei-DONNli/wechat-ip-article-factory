# 公众号标题生成规则

标题不是附属文案，而是发布输入的一部分。

这个 skill 在进入发布版锁定、发布包 ready 或远程创建草稿前，必须明确处理标题。

## 1. 标题参考源 gate

生成标题前必须先看参考，不能只凭模型感觉起标题。

最低参考源：

- 本文核心判断、原始标题或工作标题
- `content-factory/writing-assets/作者公众号风格基线.md`
- `content-factory/writing-assets/published-links-index.md`
- `content-factory/writing-assets/published-articles-snapshot.md`
- 最近一份 `content-factory/writing-assets/风格复盘/` 下的公众号风格反思候选

如果历史标题样本暂时不可用，必须说明缺口，不能假装已经参考。

参考不是照抄。参考的目标是提取标题结构、判断强度、语气边界和读者钩子。

## 1.5 创造运行时发散

生成标题前读取 `creative-runtime.md`，先确认稳定核心，再做标题发散。

标题候选不要只是同义改写，至少覆盖这些类型中的 3 类：

- 熟悉判断型：读者一眼懂
- 反常识型：打破误解
- 人格化判断型：有作者立场
- 冲突型：指出 A 与 B 的矛盾
- 系统型：从事件推到长期结构

每个标题仍必须忠于正文核心，不为了点击率偏题。

## 2. 默认产出

默认生成 `3-5` 个标题候选，并且：

- 只能有 `1` 个推荐标题
- 其余作为备选标题
- 需要说明推荐理由

如果用户已经提供标题，也不能直接跳过，仍要判断：

- 保留
- 微调
- 重写

## 3. 标题判断标准

标题要同时满足：

- 忠于文章核心判断
- 符合公众号阅读习惯
- 有吸引力，但不过度标题党
- 尽量带出对象、冲突、判断、代价、收益或反常识中的至少一种

不要把标题写成：

- 空泛口号
- 新闻播报句
- 过长工作标题
- 与正文结论不一致的夸张钩子

## 4. 作者风格约束

默认更接近这些方向：

- 从一个现象、误判或趋势切入
- 标题里有明确判断，不做中性搬运
- 能体现“问题不在 A，而在 B”这一类认知转折
- 尽量像人写出来的判断，不像运营口号

可优先考虑的结构：

- `A，不等于 B`
- `真正的问题，不是 A，而是 B`
- `别只看 A，你真正该看的是 B`
- `为什么 X 正在变成 Y`
- `与其说是 A，不如说是 B`

这只是启发，不是固定模板。不能机械套壳。

## 5. 与正文的同步要求

一旦标题确定，发布链路中的标题必须同步一致：

- 发布版 Markdown
- `article.json`
- 公众号 HTML 标题区
- 发布包 HTML
- 远程草稿标题

如果用户反馈标题不对，不能只改其中一个位置。

## 6. 最小输出格式

处理标题时，至少应给出：

- `参考来源`：实际读取或使用了哪些标题参考
- `处理判断`：保留 / 微调 / 重写
- `推荐标题`：1 个
- `备选标题`：2-4 个
- `一句理由`：为什么推荐这个标题

## 7. 何时必须重做标题

出现以下情况时，标题必须重做或至少重评：

- 用户新增了核心概念或核心判断
- 用户说“这个标题不对”
- 文章主结论被改写了
- 文章从候选稿进入发布版时，标题仍是临时工作名
- 草稿箱首屏反馈显示标题弱、偏、空或不够像作者
